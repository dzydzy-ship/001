# 启动器与局域网访问（换电脑也能一键跑）

> 面向：拿到压缩包要在**另一台电脑**上启动、或者要把页面**给同网段的同学 / 评委 / 客户**看的人。
> 一句话：解压后双击 `一键启动.bat`，剩下的事启动器自己处理；对方打不开就先双击一次 `允许局域网访问.bat`。

---

## 一、旧版为什么「换台电脑就不好使」

旧版 `一键启动.bat` 只解决了「在作者这台电脑上启动」，换机器或换网络就会卡在下面任何一处：

| # | 旧版做法 | 换电脑后的后果 |
|---|---|---|
| 1 | 固定 `--host 127.0.0.1 --port 8000` | `127.0.0.1` 是**回环地址**，只指「本机自己」。别的电脑在浏览器里输 `127.0.0.1:8000` 打开的是**它自己**，永远看不到你的服务 |
| 2 | `where python` 有结果就算通过 | Windows 10/11 自带一个 **Microsoft Store 的 `python.exe` 空壳**（`...\WindowsApps\python.exe`），`where` 能查到，但一执行就跳应用商店 / 直接失败 |
| 3 | 只判断 `.venv\Scripts\python.exe` 文件在不在 | 虚拟环境**不能跨电脑复用**：`pyvenv.cfg`、`Scripts\*.exe` 里写死了原机器的 Python 路径。文件在、一跑就报 `No Python at 'C:\Users\旧用户名\...'` |
| 4 | 端口写死 8000，不检查占用 | 目标机器上 8000 常被别的程序（另一个 Python、Docker、代理）占着，uvicorn 直接 `address already in use` 退出 |
| 5 | `pip install` 只走 PyPI 官方源 | 国内网络下经常超时/半途失败，报一堆 `Read timed out` |
| 6 | `start ... & Start-Sleep 5 & 打开浏览器` | 固定等 5 秒。首次启动要建库、写种子数据、联网采热点，5 秒根本不够，浏览器打开是「无法访问此网站」 |
| 7 | 不管 Windows 防火墙 | 服务起来了，本机 `127.0.0.1` 也能开，但**别的电脑被防火墙挡在外面**（表现为一直转圈、连接超时） |
| 8 | 没有诊断手段 | 出错只有一片红字，看不懂也没法求助 |

所以「改成更泛用」不是把 `127.0.0.1` 换成 `0.0.0.0` 就完事——那只是第 1 条，剩下的换台机器照样会踩。

## 二、新版怎么解决

主逻辑从 `.bat` 搬到了 **PowerShell**（`scripts\launcher.ps1`），`.bat` 只负责「找到 PowerShell 并把参数传进去」。

**为什么用 `.bat` + `.ps1` 两层**：`.bat` 里的中文在 UTF-8 / GBK 之间极易乱码（旧版就踩过），
而 PowerShell 脚本带 UTF-8 BOM 时，中文字符串在任何系统区域设置下都能正确显示。
因此 `.bat` 保持**纯 ASCII + CRLF**，所有中文提示都由 `.ps1` 输出。

| 环节 | 新版行为 | 对应旧版问题 |
|---|---|---|
| Python 探测 | 依次尝试：`py -3` → `py -0p` 列出的每个版本 → PATH 里的 `python` / `python3` → 注册表 `Python\PythonCore\*` → 常见安装目录通配；**每个候选都真跑一次** `python -c "import sys;print(...)"` 校验，版本低于 3.10 或跑不起来就跳过 | 2 |
| `.venv` 校验 | 不只看文件在不在，而是实跑 `.venv\Scripts\python.exe -c "import sys;print(sys.prefix)"`，要求输出**等于当前目录下的 .venv**。不通过就把旧目录改名成 `.venv.broken-年月日-时分秒`（不直接删，方便事后查），再重建 | 3 |
| 依赖 | 先做 10 个关键模块的 import 自检（fastapi / uvicorn / sqlalchemy / pydantic / httpx / yaml / apscheduler / openpyxl / xlrd / multipart）；缺了才装。装的时候依次尝试 **PyPI 官方 → 清华 TUNA → 阿里云 → 腾讯云**，任一源成功即停 | 5 |
| 端口 | `APP_PORT`（默认 8000）只是**首选**端口。被占用就自动往后顺延，最多试 30 个；启动前还会扫一遍 8000–8020 的 `/health`，发现服务**已经在跑**就只打开浏览器、不再起第二个进程（避免两个进程同时写同一个 SQLite 文件） | 4 |
| 监听地址 | 默认 `0.0.0.0`（局域网可访问），启动后用 `Get-NetIPAddress` 找出真实局域网 IP 并打印；想只给本机用：`-Local` 参数或 `.env` 里 `APP_HOST=127.0.0.1` | 1 |
| 就绪判断 | 不再固定睡 5 秒，而是**轮询 `/health`**，最多等 90 秒（首次启动要建库 + 采热点），`{"status":"ok"}` 回来后才开浏览器、才打印成功横幅 | 6 |
| 防火墙 | 单独提供 `允许局域网访问.bat` → `scripts\allow_firewall.ps1`：非管理员时自动弹 UAC 提权，加一条入站规则（TCP 8000–8020、仅本地子网、所有网络配置文件），结果写到 `logs\防火墙结果.txt`。启动时如果检测到没这条规则，会提醒一次 | 7 |
| 排障 | 每次启动写 `logs\最近一次启动.txt`（时间 / 目录 / Python 版本 / 监听地址 / 本机与局域网 URL）；`诊断工具.bat` 生成 `logs\诊断报告.txt`，覆盖系统、路径风险、Python、venv、依赖、端口占用进程、局域网 IP、防火墙状态、`import app.main` 自检、上次启动记录 | 8 |

### 一次启动的完整流程

```
双击 一键启动.bat
   └─ cmd 检查 scripts\launcher.ps1 存在 → powershell -ExecutionPolicy Bypass -File scripts\launcher.ps1 %*
        ├─ 读 .env（不覆盖系统已设置的环境变量）
        ├─ 决定监听地址：-Local > .env APP_HOST > 默认 0.0.0.0
        ├─ 决定首选端口：-Port > .env APP_PORT > 默认 8000
        ├─ [先看] 8000..+20 里是否已有本服务在跑 → 有就直接开浏览器退出（退出码 0）
        ├─ 找 Python / 校验 .venv / 装依赖（首次 1–3 分钟）
        ├─ 选实际端口（被占则顺延）
        ├─ 防火墙规则不存在且监听 0.0.0.0 → 打印提醒（不阻塞）
        ├─ 写 logs\最近一次启动.txt
        ├─ Start-Process .venv\Scripts\python.exe -m uvicorn app.main:app --host <bind> --port <chosen>
        ├─ 轮询 /health（最长 90 秒）
        ├─ 通过 → 打开浏览器 → 打印地址横幅 → 前台守护子进程
        └─ Ctrl+C / 关窗口 → 停止服务
```

### 退出码（排查时有用）

| 退出码 | 含义 | 看哪里 |
|---|---|---|
| 0 | 服务正常退出 / 检测到已在运行 | — |
| 2 | 本机没有可用的 Python 3.10+ | 窗口里的安装建议 |
| 3 | 创建 venv 失败，或依赖安装全部下载源都失败 | 窗口日志 + `logs\诊断报告.txt` |
| 4 | 服务启动失败（进程退出 / 90 秒未就绪 / 端口全被占） | uvicorn 日志 |
| 9 | 启动器自身异常（脚本报错） | 窗口里的异常信息 |

## 三、怎么用

### 启动（本机）

双击 `一键启动.bat`。第一次会自动装环境，窗口里会打印：

```
   本机访问    http://127.0.0.1:8000
   局域网访问  http://192.168.1.23:8000
```

### 给同一局域网的其他电脑 / 手机看

1. **运行服务的那台电脑**双击一次 `允许局域网访问.bat`（弹 UAC → 点「是」），只需一次；
2. 把窗口里「局域网访问」那一行的地址发给对方（注意是 **`192.168.x.x` / `10.x.x.x`** 这种地址，不是 `127.0.0.1`）；
3. 对方在浏览器打开即可。手机连同一个 Wi-Fi 也能打开。

### 命令参数

```bat
一键启动.bat -Port 9000      :: 指定首选端口（被占用照样会自动顺延）
一键启动.bat -Local          :: 只允许本机访问，等价于监听 127.0.0.1
一键启动.bat -NoBrowser      :: 不自动开浏览器
诊断工具.bat                 :: 环境自检
允许局域网访问.bat            :: 加防火墙规则（管理员）
```

`.env` 里也可以配（启动器优先用命令行参数）：

```ini
APP_HOST=0.0.0.0
APP_PORT=8000
```

### 撤销防火墙规则

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\allow_firewall.ps1 -Remove
```

## 四、安全提醒（重要）

本项目**没有登录 / 鉴权**，页面上的接口（商品、内容、匹配、设置里的计价口径）对能访问到的人都是敞开的。

- `0.0.0.0` 只适合**可信的家用 / 办公室局域网**：自己家的 Wi-Fi、和小组成员在同一个路由器下。
- **不要**在咖啡厅、酒店、展会等公共 Wi-Fi 下开着 `0.0.0.0`；演示时如果必须连公共网络，就把 `.env` 改回 `APP_HOST=127.0.0.1` 用本机演示。
- 防火墙规则已经限定 `RemoteAddress = LocalSubnet`，公网 IP 进不来；但仍**不要**在路由器上做 8000 端口映射 / DMZ。
- 需要**公网**演示怎么办：用 `ngrok http 8000`、`cloudflared tunnel --url http://127.0.0.1:8000` 或 Tailscale 这类隧道工具，用完立即关掉；它们默认是公网可达地址，务必知悉风险。
- 数据是本机 `data\app.db`，把压缩包发给别人时注意里面已经包含你在本机录入的商品 / 报价。

## 五、换电脑 / 打不开时的排查顺序

1. **看窗口打印的地址**：是不是把「本机访问」的 `127.0.0.1` 发给了别人？换成「局域网访问」那行。
2. **对方和本机是不是同一网段**：本机 `ipconfig` 看 IPv4 地址（如 `192.168.1.23`），对方也应是 `192.168.1.x`。手机可能连了访客网络（另一个网段）。
3. **本机自测局域网地址**：在本机浏览器打开 `http://192.168.1.23:8000`（用自己机器的 IP，不是 127.0.0.1）。能打开说明服务没问题，问题在防火墙或网络隔离。
4. **防火墙**：双击 `允许局域网访问.bat`。`诊断工具.bat` 里「防火墙」一行会显示是否已放行。
5. **AP 隔离**：公司 / 学校 / 酒店 Wi-Fi 常在路由器上禁止客户端互访。用手机热点把两台电脑连在一起再试，能通就是 AP 隔离。
6. **杀毒 / 安全软件**（360、火绒、电脑管家）可能拦 `python.exe` 监听端口，临时退出重试。
7. **VPN / 代理**：开着全局代理或 VPN 时，局域网请求可能被拦或走错网卡，临时关掉。
8. **路径问题**：放在 OneDrive 同步目录里，SQLite 的 `-wal` 文件可能被同步占用；路径特别长（>180 字符）也可能出错。建议 `D:\店子宠物` 这类短路径。
9. 还不行：`诊断工具.bat` → 把窗口内容和 `logs\诊断报告.txt` 发出来。

## 七、验证记录

测试环境：Windows 10.0.26300（64 位）、Python 3.14.7、**非管理员账号**、系统开着代理（`127.0.0.1:7897`）。测试都在源码的干净副本里跑，避免污染交付目录；每次都用 `-Port 81xx -NoBrowser` 并设 `NOPAUSE=1` 便于自动化。

| 场景 | 做法 | 结果 |
|---|---|---|
| 全新副本冷启动 | 拷贝一份没有 `.venv`、没有 `logs` 的目录，双击 `一键启动.bat` | 自动找到 Python 3.14.7（`%LOCALAPPDATA%\Python\pythoncore-3.14-64\python.exe`）→ 建 `.venv` → 从 PyPI 官方源装完 30 个包 → 服务监听 `0.0.0.0:8123` → `/health` 返回 `{"status":"ok"}`、`/` 返回 200（84,317 字节页面）；从开始到可用共 170 秒（含装依赖） |
| 本机 + 局域网双地址 | 用禁代理的原生请求分别打 `http://127.0.0.1:8123/` 与 `http://172.18.239.91:8123/` | 四个请求全部 200：回环 `/health` 15 字节、局域网 `/health` 15 字节、两个 `/` 都是 84,317 字节。说明监听 `0.0.0.0` 后本机、局域网两个地址都通 |
| 首选端口被占用 | 先用 python 占住 8126，再以 `-Port 8126` 启动 | 窗口提示「端口 8126 已被别的程序占用（被 python / PID 9164 占用），自动换端口」，实际起在 8127，健康检查通过 |
| 坏 `.venv`（跨机残留） | 造一个 `pyvenv.cfg` 里 `home=` 指向 `C:\NoSuchPython` 的假 `.venv` | 提示「旧的 .venv 不可用（虚拟环境不能跨电脑复用），已改名保存为 `.venv.broken-20261028-155808`」，随后重建并成功启动在 8128 |
| 重复双击 | 服务已在 8123 运行时再执行一次 `一键启动.bat` | 2.2 秒、退出码 0，只提示「检测到服务已经在运行」并打开地址，没有起第二份进程 |
| 诊断工具 | 全新副本里执行 `诊断工具.bat` | 5.3 秒输出完整报告（系统 / 路径提示 / Python / 虚拟环境 / 端口 / 局域网 / 防火墙 / 自检 / 上次启动记录），并写入 `logs\诊断报告.txt`（777 字节） |
| 关闭即退出 | 手动结束服务进程，观察启动器窗口 | 启动器随服务退出，`一键启动.bat` 返回退出码 0 |

未在本机实测的两项（受环境限制，逻辑已写但需在目标机确认）：① `允许局域网访问.bat` 需要管理员权限，本机测试账号非管理员，UAC 提权无法完成，只做了脚本语法检查；② 真正的「另一台电脑打开本机 IP」需要第二台设备，本机只验证到「局域网 IP 在本机可访问」，跨机能否打开还取决于防火墙规则与路由器 AP 隔离（对应排障第 4、5 条）。

排错记录（供后续维护参考）：早期版本用 `where python` 判 Python，会命中 Microsoft Store 的空壳；健康检查原先用 `Invoke-WebRequest`，在开着系统代理或被 VPN/TUN 过滤回环端口的机器上会长时间卡住（曾卡在扫描 8138 端口的 `SYN_SENT` 上），现在改成先查系统监听表再用**禁用代理**的原生 HTTP 请求检查 `/health`，同一场景从「卡住不动」变成毫秒级返回。
