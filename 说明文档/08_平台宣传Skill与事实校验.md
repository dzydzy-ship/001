# 08 · 平台宣传 Skill 与事实校验（防 AI 幻觉）

本轮升级解决三件事：

1. **把小红书 / B站 / 抖音三个平台的宣传算法，蒸馏成"宣传 Skill"文档**，生成内容时整篇注入提示词，让模型按平台规则写，而不是"通用文案改个壳"。
2. **生成前先做产品分析**：程序化提炼商品事实（卖点 / 人群 / 场景 / 痛点 / 证据 / 限制 / 资料缺口 / 各平台切入角度），先生成一份"事实清单"再交给大模型，从源头减少幻觉。
3. **生成后做事实校验**：数字白名单、成本泄露、无依据宣称、商品名命中四类检查；发现严重问题会自动带问题清单重写一次。

---

## 一、平台宣传 Skill

### 文件位置

| 平台 | 配置（算法要点/限制） | Skill 全文 |
| --- | --- | --- |
| 小红书 | `config/platforms.yaml` → `xiaohongshu` | `config/platform_skill_xiaohongshu.md` |
| B站 | `config/platforms.yaml` → `bilibili` | `config/platform_skill_bilibili.md` |
| 抖音 | `config/platforms.yaml` → `douyin` | `config/platform_skill_douyin.md` |
| 电商详情页 | `config/platforms.yaml` → `ecommerce` | `config/platform_skill_ecommerce.md` |

每个 Skill 文档六节：**平台怎么给流量 → 内容结构公式 → 标题公式 → 开头钩子 → 写作红线 → 把商品分析用起来**。

### 怎么生效

- 代码：`app/services/platform_skill.py` 的 `load_platform_skill(platform)` 读取 md 全文，`_build_prompt()` 把它拼进系统提示词（在通用规则之后、平台硬性限制之前）。
- **改 md 文件即时生效**（按文件 mtime 缓存），不用改代码、不用重启服务。
- 没写 skill 文档的平台会自动降级为"只用 platforms.yaml 的算法要点"，不会报错。

### 本次蒸馏的关键结论（写进 skill 的规则）

- **小红书**：双列瀑布流，首图+标题决定点击率；点击后互动权重 **收藏 > 评论 > 点赞**，好内容再吃搜索长尾。标题 ≤20 字，口语化、带情绪或数字，标签 8~10 个。
- **B站**：推荐 + 关注双引擎，**完播率是第一指标**，其次三连（点赞/投币/收藏）与弹幕评论。标题 ≤40 字，反套路/疑问/结论前置；开头 30 秒必须给"值得看完的理由"；适合测评/教程/对比结构。
- **抖音**：推荐流，**前 3 秒留存与完播率**决定是否进下一个流量池，其次互动率。标题 ≤55 字；脚本按 `0-3 秒钩子 / 3-10 秒问题放大 / 10-25 秒演示 / 25-30 秒引导` 分镜，每镜写景别、运镜、字幕、时长。
- **电商详情页**：搜索驱动，关键词命中 + 参数完整 + 评价/售后决定转化；标题 ≤60 字，先讲参数再讲场景。

## 二、生成前产品分析（Product Brief）

### 接口

`POST /content/analyze`，请求 `{"product_id": 1, "platform": "xiaohongshu"}`（platform 可省略）。

返回字段：

| 字段 | 含义 |
| --- | --- |
| `name / brand / category / price / promotion / brand_tone` | 商品基础信息 |
| `core_points` | 核心卖点（来自 selling_points + tags.功能） |
| `audience` | 目标人群：`描述 / 需求 / 顾虑` |
| `scenes` | 使用场景 |
| `pain_points` | 用户痛点 |
| `evidence` | 证据 / 背书 |
| `restrictions` | 限制与禁忌（合规红线） |
| `hot_topic_types` | 可蹭热点类型（选题参考，**不是**限制） |
| `facts` | 事实清单（逐条，文案只能引用这些） |
| `numbers` | 允许出现在文案里的数字白名单 |
| `gaps` | 资料缺口（生成时会弱化，前端红色提示商家补全） |
| `angles` | 四个平台各自的切入角度建议 |
| `doc` | 拼好的可读文本，直接作为提示词的"产品分析"部分 |

**特点**：纯规则化、**零大模型调用**，秒回；只做提炼归类，**不新增事实**（所以不会自己编卖点）。

### 怎么用

界面「内容生成」面板：选择商品 → 自动展示产品分析卡 → 选择平台 → 展示该平台算法要点与切入角度 → 点「生成」。

## 三、事实校验（防幻觉）

代码：`app/services/content.py` 的 `fact_check(content, product, brief)`。

| 检查 | 触发 | 级别 |
| --- | --- | --- |
| 数字白名单 | 文案出现「允许出现的数字」之外的数字 | 高（价格语境不一致）/ 提示（其他） |
| 成本泄露 | 出现进货成本、利润率等内部数据 | 高 |
| 无依据宣称 | 专利、认证、获奖、销量第一、国家级、检测报告、疗效、治疗、根治、100% 有效等 | 高 |
| 商品名命中 | 标题/正文/标签/脚本里没出现商品名或品类关键词 | 提示 |

- `passed = 没有 high 级问题`；提示级问题只展示不阻断。
- 生成后若有 high 级问题：**自动把问题清单带回去重写一次**，取问题更少的版本。
- 校验结果合并在内容的 `audit_result` 里：`audit_result.fact_check` = `{passed, issues, high_count, warn_count, allowed_numbers}`，notes 里以「【事实】」「【提示】」前缀显示，前端红色/橙色区分，并给内容卡加"事实校验通过/未通过"徽章。

### 合规词误报的处理

- 「最」只有在"最好/最低/最便宜/最受欢迎"等**极限词语境**才拦截；「最怕/最近/最多」这类日常表达不拦截。
- 「第一」只有在"第一名/第一品牌/销量第一/全网第一"才拦截；「第一步/第一次」不拦截。
- 这样既守住广告法红线，又不会把正常口语误判成违规。

## 五、实测结果（2026-10，DeepSeek deepseek-chat）

- 商品 1「316 不锈钢保温杯」→ **小红书**：3.1 秒，标题 13 字，正文只用了事实清单里的信息（316 内胆 / 500ml / 12 小时保温 / 129 元 / 材质检测报告），**事实校验通过**，极限词校验通过（"最戳我"未被误判）。
- 商品 2「高倍防晒霜」→ **抖音脚本**：5.2 秒，8 个分镜（痛点开场 / 问题放大 / 产品出场 / 质地演示 / 卖点演示 / 证据展示 / 结论 / 互动引导），每镜带景别、运镜、字幕、时长，**事实校验通过**。
- 商品 3「客制化键盘」→ **B站**：标题 40 字内、结论前置、先参数后缺点、结尾三连引导；数字校验只把"预算 400 内"标为提示（不影响通过）。

## 六、注意事项与限制

1. 三个 Skill 是**基于公开平台规则与运营经验蒸馏的最佳实践**，不是平台官方文档；平台算法会调整，建议每季度复核一次 md 文件。
2. 事实校验是**程序化粗筛**：能拦住明显编造（价格、功效、认证），但"措辞是否夸大"仍需人工最终确认；界面已标注"事实与合规请人工最终确认"。
3. 产品分析的质量取决于商品资料完整度：**资料缺口**会在前端红色提示，补全商品资料（规格、证据、人群、场景）后内容会明显更贴合。
4. 平台 Skill 文件是纯 markdown，运营同学可以直接改；改完刷新页面即生效（服务端按 mtime 缓存）。
