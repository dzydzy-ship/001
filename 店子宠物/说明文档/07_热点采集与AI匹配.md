## 二、数据来源（`config/sources.yaml`）

默认启用 4 个源，全部是**公开可直接访问**的 JSON 接口，不需要登录、不需要 API Key：

- `toutiao` —— 今日头条热榜（约 50 条）
- `bilibili` —— B 站排行榜（约 100 条）
- `bilibili_parts` —— B 站 8 个分区榜（游戏/美食/时尚/数码/运动/科技/娱乐/生活），每榜 12 条，**保证「游戏、食品、美妆、运动」等板块有真实内容**
- `zhihu_daily` —— 知乎日报（最新 + 头条）

另外保留 `dailyhot` 作为**可自部署**的可选聚合源（默认 `enabled: false`）：如果你想用 DailyHotApi 聚合几十个平台，自己 `docker run -p 6688:6688 imsyy/dailyhot-api:latest` 起来，再把 `base_url` 指过去、`enabled` 改成 `true` 即可。公开实例 `api-hot.imsyy.top` 目前域名已失效，别直接用。

> 想加新板块或新来源：在 `sources.yaml` 的 `sources` 里加一项、在 `category_keywords` 里补该板块的关键词、在 `source_category_map` 里补「来源/分区 → 板块」的映射；需要新解析逻辑时在 `app/services/collectors/` 加一个模块并在 `collectors/__init__.py` 注册。

## 三、商品标签

- 新增字段：`products.tags`（JSON）。老数据库启动时会自动 `ALTER TABLE` 补列，不用手动迁移。
- 生成方式：商品结构化提取时，大模型按 7 个维度输出标签；演示数据（3 个 demo 商品 + 4 款飞机）已经预置了标签。
- 标签可以在「商品管理 → 编辑」里手工调整（同一套 JSON 结构）。

示例（露营灯）：

```json
{
  "品类": ["露营灯", "户外照明"],
  "功能": ["三档调光", "长续航", "IPX4 防水", "便携折叠"],
  "场景": ["露营", "夜钓", "停电应急"],
  "人群": ["露营爱好者", "户外新手"],
  "痛点": ["夜间照明不足", "户外怕水"],
  "价格带": "百元档",
  "可蹭热点类型": ["户外露营", "季节"]
}
```

## 四、AI 匹配怎么跑

两阶段，避免把上百条热点和 7 个商品全量两两调大模型（既慢又贵）：

1. **程序初筛**：取最新的、非敏感的热点作为候选池（默认最多 40 条，可按请求参数调整），并给每对算好 R/T/A 三个程序分项。
2. **大模型挑选**：逐个商品把候选热点标题（带编号）交给大模型，让它挑出最多 2 个真实可结合的机会——顺带给出关联逻辑、创意方向、内容形式、风险清单和 P/C 分。
   - TF-IDF 只能算字面重合，挑不出「防晒霜 × 妆容」「保温杯 × 入冬」这种语义关联，所以这一步交给大模型。
3. **汇总**：`S = 0.30R + 0.25T + 0.20A + 0.15P + 0.10C`，生成机会卡。
   - 有 AI 判定时，**R 采用大模型给出的关联强度**（`r_score`）；TF-IDF 值另存 `subscores.r_tfidf` 备查。
   - Mock 模式（没配 Key）自动退回「程序相关性 Top2 + 规则判断」，离线也能演示。

接口：

```
POST /matching/run
{ "product_ids": null, "hotspot_ids": null, "hotspot_limit": 40, "judge_limit": 12 }
```

- `hotspot_limit`：候选热点池大小（1~200）
- `judge_limit`：本次最多生成多少张机会卡（1~100）
- 同一个「商品 × 热点」组合不会重复生成，反复点按钮不会堆重复卡

耗时参考：7 个商品、12 张卡，真实大模型大约 **25~45 秒**。

## 五、页面怎么用

1. 启动服务后打开 http://127.0.0.1:8000
2. 进「热点看板」→ 点「刷新热点」，会实时拉取热榜（实测一次约 160+ 条）
3. 用上方的板块筛选项（带数量）按板块过滤，比如只看「游戏」「食品」
4. 点看板右上角「AI 匹配商品」→ 等 20~60 秒，下方出现机会卡：
   商品 ✕ 热点、综合分、R/T/A/P/C、关联逻辑、创意方向、建议形式、风险提示

## 六、已知限制（答辩时可以直接说）

- 热榜接口是公开接口，**没有 SLA**、可能限流或改字段；采集器已做单源失败隔离（一个源挂掉只打日志，不影响其他源），但长期生产使用建议自己部署聚合源或走官方开放平台。
- 采集仅取公开榜单信息（标题/描述/链接/热度），不抓正文、不登录、不绕风控；接入媒体平台内容时需遵守平台协议与版权要求。
- 当前语义匹配依赖大模型，一次完整匹配约 20~60 秒；商品多、热点多时可以只对选中的商品跑匹配（传 `product_ids`）。
- TF-IDF 只是**排序与备查**信号，不是最终相关性结论。
